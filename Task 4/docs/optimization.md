# x86 优化说明

## 已实现

1. **共享 GPR 轮函数** `sm3_compress_rounds_gpr`  
   - 宏 `SM3_ROUND` 展开 FF/GG/P0 与移位  
   - `sm3_t_rol(j)` 计算 `(T_j <<< j)`，避免易错常量表  

2. **SIMD 大端装载**  
   - 避免 16 次标量移位拼字  

3. **SIMD 消息扩展**  
   - `P1`、`<<<15`、`<<<7` 在向量单元完成  

4. **SIMD 生成 W′**  
   - AVX2：8×u32；AVX512：16×u32  

5. **编译隔离**  
   - `sm3_avx2.c` 单独 `/arch:AVX2`  
   - `sm3_avx512.c` 单独 `/arch:AVX512`  
   - 避免污染 ref 目标指令集  

6. **运行时 CPUID + XGETBV**  
   - 检查 OS 是否保存 YMM/ZMM（XCR0）  

## 后续可增强（加分方向）

| 项 | 思路 |
|----|------|
| 扩展与压缩软件流水 | 先扩 8 个 W 再压 8 轮，隐藏延迟 |
| 4 路多缓冲 | 4 个独立 state 用 AVX2 并行轮函数 |
| 预计算 `T<<<j` 表 | 微幅减少压缩侧移位 |
| 汇编调度 | 手工安排 `rorx`/`lea` 等 |

## 多缓冲（推荐吞吐路径）

单缓冲加速比受限时，应采用 **4 路多缓冲**（见 [multibuffer.md](multibuffer.md)）：  
扩展与压缩均在 4 个 lane 上并行，合计吞吐通常明显高于 4× 顺序 ref。

验收：`test_mb`；对比：`bench_sm3` 中的 `ref4` 与 `mb4`。

### 如何解读

1. **正确性已对齐**：向量测试 + 2000 组随机长度交叉对比全部通过。  
2. **单缓冲混合路径未必然快于标量**：  
   - 64 轮 `A..H` 强串行，占比最大；  
   - `W[j]` 依赖 `W[j-3]`，扩展无法 8-lane 无脑并行；  
   - 当前 AVX2 扩展在逐步计算中穿插向量 `P1`，带来进/出 XMM 的额外开销。  
3. **作业交付重点**：混合分工清晰、可切换、可测、可回退；性能表用于分析而非唯指标。  
4. **若要明显加速（加分）**：多缓冲（同时哈希 4/8 条独立消息）、扩展/压缩软件流水、手写汇编调度。

## 性能预期（写报告可用）

单缓冲 SM3 仅优化装载/扩展时，加速比通常 **温和甚至暂时变慢**；这是算法依赖结构决定的，不是实现“没跑通”。  
多缓冲才能把 SIMD 宽度吃满，可作为报告扩展章节。
